# 동시 명중 개인 보상 조사 (2026-11-12)

## 실제 RL 보상 연결

`USH_ShooterInteractor::PerformAgentActions_Implementation`은 모든 `PrepareShot` 결과를 모은 뒤
배열 순서대로 `ResolveShot`을 호출한다. `UCombatStatsComponent::ApplyDamage`는 이 순서에 따라
공격자의 `DamageDealtAccum`과 `KillsAccum`을 기록한다.

`USH_ShooterTrainingEnv::ComputeIndividualReward`는 이 누산값을 실제 학습 보상에 직접 사용한다.

```text
DamageDealtWeight * damage / 100
+ KillBonus * kills
- MissWeight * misses
```

따라서 처리 순서에 따른 개인별 피해량과 킬 귀속 차이는 실제 PPO 학습 보상에도 반영된다.
`TeamSpirit`은 개인 보상과 팀 평균을 혼합하지만, 값이 1보다 작은 동안에는 개인별 차이를
완전히 제거하지 않는다.

## 재현 결과

두 공격자가 각각 피해 10을 가하는 실제 프로덕션 경로 테스트를 추가했다.

- 대상 HP 25: 처리 순서를 뒤집어도 각 공격자의 피해는 10, 킬은 0, 실제 전투 보상은 0.1이다.
- 대상 HP 15: 먼저 처리된 공격자는 피해 10과 보상 0.1을 받고, 나중 공격자는 남은 피해 5와
  킬을 받아 보상 0.55를 받는다. 처리 순서를 뒤집으면 두 공격자의 집계와 보상도 뒤집힌다.
- 두 처리 순서 모두 팀 합계는 피해 15, 킬 1, 전투 보상 0.65로 같다.
- 단독 비치명 피해 10의 보상 0.1과 단독 치명 피해 10의 보상 0.6도 같은 프로덕션 계산식으로
  확인했다.

## 결론과 현재 동작

이번 조사로 실제 RL 보상이 동시 명중의 처리 순서에 의존한다는 사실을 확인했다.

기존 보상 문서는 `KillBonus`를 마지막 명중자에게 주는 보상으로 정의한다. 일반적인 순차 공격은
현재 구현이 이 규칙과 일치한다. 반면 같은 의사결정에서 미리 준비된 동시 공격에는 시간적인
마지막 명중자가 없으며, 현재는 액션 배열 또는 AgentId 순서가 피해와 킬 공로를 결정한다.

균등 배분, 피해 비례 배분, 공동 킬 중 어느 규칙이 게임 의도에 맞는지는 기존 코드와 문서만으로
결정할 근거가 없다. 따라서 이번 변경은 처리 순서 의존성을 실제 보상 계산으로 검증하는 테스트를
추가하되, 현재의 피해·킬 공로 배분 동작과 보상 규칙은 변경하지 않는다.
