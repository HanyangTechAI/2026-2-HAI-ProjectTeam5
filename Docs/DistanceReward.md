## * 현재 코드 이해

"멀어지려는 경향" 을 보상이 만들고 있는지 확인: **보상 항 중 거리를 보는 것이 무엇인가.**

### USH_ShooterTrainingEnv::ComputeIndividualReward — 거리를 보는 항 확인

| 항 | 거리를 보는가 | 기록 결과 |
|---|---|---|
| `DamageDealtWeight` / `DamageTakenWeight` | **간접** | 명중 확률을 통해서만. 적 캡슐의 각 크기가 거리에 반비례 |
| `KillBonus` / `DeathPenalty` | 간접 | 위와 같다 |
| `MissWeight` | 간접 | 멀면 빗맞힘이 늘어 벌점이 는다 |
| `TimePenalty` · 라운드 시계 비용 | **없음** | 상수. 어디에 서 있든 같다 |
| `OutcomeReward` · 팀 스피릿 | **없음** | 라운드 결과만 본다 |
| **`SeeWeight` · `AlignWeight`** | **없음** | ← **원인.** 보이기만 하면 거리와 무관하게 전액 |

`AGun::Range` = `USH_VisionComponent::MaxRange` = **6000 cm** 인데 아레나 지름은
2 x `ArenaRadius` = **3500 cm** 다. 즉 **아레나 안 어느 두 점에서도 셰이핑이 100% 수확된다.**

```
if (Vision->IsHostileVisible()) { Reward += ShapingScale * SeeWeight; ... AlignWeight * align^4; }
```

반면 명중은 거리에 반비례해 사라진다. 적 캡슐 반경 42 cm 의 각 폭과,
조준 최소 구간(`TurnBins` 의 ±10°/s x 결정 0.05초 = **0.5°**) 으로 나눈 "조준 양자 수":

| 거리 | 표적 각 폭 | 조준 양자 수 | 셰이핑 (수정 전) |
|---|---|---|---|
| 2202 cm | 2.19° | 4.4 | **0.0105** |
| 1545 cm | 3.11° | 6.2 | **0.0105** |
| 1200 cm | 4.01° | 8.0 | **0.0105** |
| 600 cm | 8.01° | 16.0 | **0.0105** |

600 cm 는 2202 cm 보다 조준이 **3.66배 관대**한데 보상은 **똑같았다.**
`ppo.py` 의 `MinimumAdvantage = 0.0` 이 받은 피해 벌점을 잘라 내므로 반대로 끌어당길 신호도 없다.
→ **벽에 붙어 조준만 하는 쪽이 밀고 들어가는 쪽보다 기대값이 높다.**

### ⚠ 정정 — 직전 분석의 오류

"라운드 앞 15~20초가 교전 없는 공백" 이라고 썼는데 **틀렸다.**
첫 피해가 0.3초이고 평균 라운드가 7.0~14.7초다. 대치는 없다 — 즉시, 그리고 멀리서 싸운다.
따라서 `ZoneStartSeconds` 를 줄이자는 제안도 철회한다. 오히려 그 반대 사실이 나온다:

## * 멀리 있는 것이 학습에 나쁜 효과를 주는가

**지금 당장은 아니다. 하지만 두 가지를 막고 있다.** 근거를 나눠 적는다.

### 나쁘지 않다는 근거

1. **조준은 잘 학습되고 있다.** 명중률 46.5~50% (무작위 기준선 1.3%, 스크립트 봇 65%).
2. **대치가 아니다.** 첫 피해 0.3초, 시간 초과 0%. 거리 유지가 회피로 이어지지 않았다.
3. **원거리 사격 자체는 유효 전술이다.** 히트스캔 + 산포 0 이라 멀어도 맞으면 같은 피해다.
   실제 슈터에서도 사거리 우위는 정당한 전략이고, 그걸 금지할 이유는 없다.

### 그래도 고쳐야 하는 근거

1. **이동 정책이 퇴화했다.** 우측 이동 46~51% (균등 20%), 전진 10~11% (균등 미만).
   균등분포에서 벗어난 게 아니라 **한 행동으로 무너진 것**이다. 원형 선회 하나를 찾고 멈췄다.
   TODO 1A.6c 의 "이동은 아직 학습되지 않았다" 가 더 나빠진 형태로 남아 있다.
2. **엄폐물이 학습에 전혀 참여하지 않는다.** `IsHostileVisible()` 은 LOS 를 요구하므로
   **엄폐물 뒤로 들어가면 셰이핑이 0 이 된다** — 셰이핑이 엄폐에 벌점을 주고 있다.
   Phase 2 에서 엄폐물을 넣은 이유 전체가 사장된다.
3. **최종 게임이 성립하지 않는다.** 출고 형태는 14x14 격자에 유닛을 놓는 오토배틀러
   (`ASH_BattleBoard`) 다. 모든 유닛이 스폰 직후 바깥 벽으로 달려가 선회한다면
   **플레이어가 어디에 놓든 결과가 같아진다.** 배치가 게임의 전부인데 배치가 무의미해진다.

> 결론: "멀다" 가 문제가 아니라 **"거리를 고를 이유가 없다"** 가 문제다.
> 거리에 보상 기울기가 0 이면 정책은 거리를 전술로 쓰지 못하고, 아무 쪽으로나 무너진다.

## * 수정 — 거리를 보는 항 두 개

### 1. 셰이핑에 근접 가중 (`SHReward::Proximity`)

`SeeWeight` / `AlignWeight` 에 `1 − d / EngageRangeCm` (지름 3500 기준) 을 곱한다.
원인 제거다 — 벽에서의 수확을 없앤다.

### 2. 접근 보상 (`SHReward::Approach`) — 감쇠하지 않음

매 결정에 `Weight x (직전 거리 − 지금 거리) / EngageRangeCm`.
차분이라 **왕복이 정확히 상쇄**되어 농사가 불가능하고, 라운드 합이
`Weight x (시작 − 끝) / Range` 하나로 접힌다.

> 퍼텐셜 기반(γΦ′ − Φ)을 쓰지 않은 이유: γ = 0.99 면 (1 − γ)|Φ| 가 매 스텝 새어 나오고,
> 거리에 비례하는 Φ 에서는 그 누수가 **가만히 멀리 서 있는 것에 대한 보상**이 된다.

### 보상 수준에서 얼마나 달라지는가 (계산값, 실측 아님)

| 거리 | 셰이핑 전 | 셰이핑 후 | 변화 |
|---|---|---|---|
| 2202 cm (실측 평균) | 0.01050 | **0.00389** | **−63%** |
| 1545 cm (실측 평균) | 0.01050 | 0.00586 | −44% |
| 1200 cm | 0.01050 | 0.00690 | −34% |
| 600 cm (교전 거리) | 0.01050 | 0.00870 | −17% |

| 항목 | 수정 전 | 수정 후 |
|---|---|---|
| 2202 → 600 cm 로 접근할 때 얻는 것 | **0** | **+0.458** (킬 보너스 0.5 와 동급) |
| 전속 접근 결정당 | 0 | +0.00714 |
| 거리에 대한 보상 기울기 | **0** | 양수, 아레나 전 구간 |

비교 기준: 시계 비용 0.0200/결정, 시간 벌점 0.0020/결정, 셰이핑 하한 최대 0.0105/결정.

## * 에디터에서 A/B 비교

같은 맵 · 스폰 · 시간 제한 · 같은 스냅샷에서 **접근 가중치 하나만** 바꾼다.
`-SHApproach=` 스위치를 넣어 BP 기본값을 건드리지 않고 켜고 끌 수 있게 했다
(PLAN.md 의 "BP 기본값은 배치 인스턴스에 전파되지 않는다" 경고를 피한다).

```
대조군 (접근 보상 끔):  -SHApproach=0
처치군:                 -SHApproach=1
```

**실행 명령 전문과 채울 비교표는 [../Snapshots/2026-11-12.md](../Snapshots/2026-11-12.md) 에 있다.**
그 파일이 이 변경을 돌리는 사람이 볼 문서다.

판정: **최근접 적이 내려가면서 명중률이 유지되면 성공.**
명중률이 같이 떨어지면 `ApproachWeight` 가 과하다 — `-SHApproach=0.5` 로 낮춰 다시 본다.
롤백은 `-SHApproach=0` 이고, 코드를 되돌릴 필요가 없다.

### 안전장치

| 위험 | 막은 방법 |
|---|---|
| 스폰 재배치·풀 재사용으로 거리가 점프 → 한 결정에 거대한 보상 | `ApproachMaxStepCm = 100`. 걸어서 닿을 수 없는 변화(최대 50 cm)는 0 으로. 없으면 정상 결정의 **72배** |
| 라운드 리셋에서 낡은 거리가 새어 들어감 | `ResetAgentEpisode` 에서 기준을 버린다 (null 검사보다 먼저) |
| 엄폐물 뒤로 들어가면 거리가 끊겨 엄폐가 벌점이 됨 | 거리를 **가시성 무시**하고 기하로 잰다 |
| 왕복으로 보상 농사 | 차분이라 정확히 상쇄된다 (테스트로 단언) |
| 학습된 스냅샷을 못 쓰게 됨 | 스키마 불변(관측 42 / 행동 12). 기존 스냅샷 그대로 `-SHResume=` 가능 |
| 돌려보지 않은 변경이 기본값이 됨 | `-SHApproach=0` 이 **수정 전과 동일한 보상**이다 |

## [요약]

1. **원인은 `SeeWeight` / `AlignWeight` 가 거리를 보지 않는 것이다.**
   사거리 · 시야(6000)가 아레나 지름(3500)보다 넓어 벽에서도 셰이핑이 전액 수확됐다.
   명중만 거리에 반비례해 사라지므로, 멀리 서는 쪽이 이득이었다.

2. **"멀다" 자체는 학습에 나쁘지 않다.** 조준은 학습됐고(명중률 47%) 대치도 없다(첫 피해 0.3초).
   문제는 **이동 정책이 우측 선회 하나로 퇴화**했고, **엄폐물이 쓰이지 않으며**(셰이핑이 엄폐에
   벌점을 준다), **배치형 오토배틀러에서 배치가 무의미해진다**는 것이다.

3. **수정 두 개.** 셰이핑에 근접 가중을 곱해 원인을 없애고, 감쇠하지 않는 접근 보상으로
   기울기를 만든다. 보상 수준에서 벽 거리 수확이 63% 줄고, 접근의 가치가 0 → 0.458 이 된다.

4. **`-SHApproach=` 로 A/B 한다.** 0 이 대조군, 1 이 처치군. 같은 스냅샷 · 같은 시간으로 두 번
   돌려 위 표를 채운다. 최근접 적이 내려가면서 명중률이 유지되는지가 판정이다.

5. **구역 축소 과제에 대한 별도 발견.** 평균 라운드가 7.0~14.7초인데 `ZoneStartSeconds` 가 20초다.
   **구역 축소는 지금 한 번도 작동하지 않는다.** 켠/끈 비교를 하려면 먼저 라운드가 20초를
   넘도록 만들거나(`ZoneStartSeconds` 를 5초로), 라운드 길이부터 측정해 조건을 맞춰야 한다.
   지금 비교하면 두 조건이 같게 나오고, 그건 구역이 무력하다는 뜻이지 영향이 없다는 뜻이 아니다.
