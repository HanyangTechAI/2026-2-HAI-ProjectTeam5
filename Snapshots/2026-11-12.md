# 2026-11-12 학습 기록

## 수정사항

학습을 돌리지 않았다. **보상에 거리 항을 넣었고 아직 빌드하지 않았다** — 돌리기 전에 컴파일부터 확인할 것.

배경과 수치는 [Docs/DistanceReward.md](../Docs/DistanceReward.md) 에 있다. 한 줄 요약:
`SeeWeight` / `AlignWeight` 가 거리를 전혀 보지 않는데 사거리·시야(6000 cm)가 아레나 지름(3500)보다
넓어서, 반대편 벽에서도 셰이핑이 전액 수확됐다. 명중만 거리에 반비례해 사라지므로 멀리 서는 쪽이 이득이었다.
실측 최근접 적 거리 1545~2202 cm.

1. **셰이핑에 근접 가중** (`SHReward::Proximity`, `SH_ShooterTrainingEnv.h`)
   `SeeWeight` / `AlignWeight` 에 `1 − d / EngageRangeCm` 을 곱한다. 2202 cm 에서 수확이 63% 줄고,
   600 cm 에서는 17% 만 준다. 원인 제거다.

2. **접근 보상** (`SHReward::Approach`, 감쇠하지 않음)
   매 결정에 `ApproachWeight x (직전 거리 − 지금 거리) / EngageRangeCm`.
   왕복이 정확히 상쇄되어 농사가 불가능하고, 라운드 합이 `W x (시작 − 끝) / Range` 하나로 접힌다.
   기본값 `ApproachWeight = 1.0`, `EngageRangeCm = 3500`(아레나 지름).
   거리는 **가시성을 무시하고** 잰다 — 시야로 재면 엄폐물 뒤로 들어갈 때 거리가 끊겨
   엄폐가 벌점이 된다.

3. **텔레포트 방호** (`ApproachMaxStepCm = 100`)
   결정 하나에 걸어서 변할 수 있는 거리는 최대 50 cm 다(양쪽이 마주 달릴 때).
   그보다 큰 변화는 스폰 재배치·풀 재사용·표적 교체이므로 접근 보상을 0 으로 만든다.
   방호가 없으면 그런 변화 한 번이 정상 결정의 **72배**(0.51)를 꽂는다.

4. **`-SHApproach=` 스위치** (`ASH_CombatTrainer`)
   `0` 이면 2 번의 접근 보상이 완전히 꺼진다. A/B 의 손잡이이자 롤백 경로다.
   보고 줄 첫 줄 끝에 `접근 w0.00` / `접근 w1.00` 이 찍힌다.
   ★ 근접 가중(1번)은 이 스위치로 꺼지지 않는다. 그쪽까지 되돌리려면 `EngageRangeCm` 을
   6000(= `MaxRange`)으로 올린다 — 가중이 아레나 전 구간에서 0.42 아래로 안 내려가 영향이 거의 사라진다.

5. **테스트** `Source/HAI_Project_TEAM5/RL/Tests/SH_RewardTests.cpp`
   Tools → Session Frontend → Automation 에서 `TEAM5.Reward` 검색.

## 돌리는 법 — A/B

에디터를 닫고, 아래 두 줄을 **같은 스냅샷 · 같은 시간**으로 차례로 돌린다.
`-SHApproach=` 하나만 다르다. `<엔진>` `<프로젝트>` 는 각자 경로로 바꿀 것.


```bash
MSYS_NO_PATHCONV=1 "<엔진>/Engine/Binaries/Win64/UnrealEditor-Cmd.exe" "<프로젝트>/HAI_Project_TEAM5.uproject" /Game/RL/Lvl_SHTrain -game -log -abslog=C:/temp/ab_w1.log -unattended -nosplash -nullrhi -nosound -SHApproach=1 -SHResume=Snapshots/2026-10-25/cum016h00m -SHTrainSeconds=1800 -SHReportInterval=60 -SHSnapshotInterval=0
```

함정은 [TODO.md](../Docs/TODO.md) 의 "헤드리스 학습 실행" 절과 같다 —

`-SHSnapshotInterval=0` 으로 A/B 실행이 스냅샷을 남기지 않게 했다. 기존 스냅샷은 건드리지 않는다.
30분(1800초)은 최소선이다. 여유가 있으면 양쪽 다 3600 으로 늘리는 쪽이 판정이 깨끗하다.

### 판정

두 로그의 `[SH_CombatTrainer]` 보고 줄을 비교한다. **마지막 3개 보고의 값**을 쓴다
(재개 직후에는 크리틱이 적응 중이라 흔들린다).

| 지표 | 로그 위치 | 기대 | 비고 |
|---|---|---|---|
| **최근접 적 (cm)** | 2번째 줄 끝 | **내려간다** | 핵심. 안 내려가면 실패다 |
| 명중률 (%) | 1번째 줄 `명중 N (…%)` | **유지** | 같이 떨어지면 `-SHApproach=0.5` 로 다시 |
| 이동 전진 (%) | 2번째 줄 `이동 전진` | 올라간다 | 현재 10~11%, 균등 20% |
| 이동 우 (%) | 2번째 줄 `이동 우` | 내려간다 | 현재 46~51% — 선회 하나로 퇴화해 있다 |
| 시간 초과 (%) | 2번째 줄 `시간초과` | **0% 유지** | 오르면 대치다. 즉시 중단 |
| 평균 길이 (초) | 2번째 줄 `평균 길이` | 짧아진다 | 붙으면 빨리 끝난다. 정상 |

**성공 = 최근접 적이 내려가고 명중률이 유지됨.**
**즉시 롤백 = `-SHApproach=0`.** 코드를 되돌릴 필요가 없다.
