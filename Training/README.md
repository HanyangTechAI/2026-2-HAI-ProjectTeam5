# 자동 학습 (Training/)

`train.bat` 을 실행하면 언리얼 학습이 헤드리스로 돌고, **1시간마다 스냅샷을 저장해 git `preMerge` 에 커밋 · push** 한다.

## 폴더

```
Training/
  train.bat, train.py, README.md
  A/                         ← 학습 이름 하나 = 폴더 하나
    run.json                 ← 시작 설정(언리얼 옵션, 시작 코드의 커밋, 시작 정책, 메모)
    cum001h00m/              ← 누적 학습 시간 = 폴더 이름 = 파일 이름 앞부분
      cum001h00m_policy.bin, _encoder.bin, _decoder.bin, _critic.bin, _meta.txt
    cum002h00m/ ...
    2026-11-13.md            ← 트레이너가 쓰는 날짜별 실행 기록
    logs/                    ← 언리얼 로그 · 실행기 로그 (git 에 올리지 않음)
  B/ ...
```

## 쓰는 법 — 메뉴

`train.bat` 을 더블클릭하면 메뉴가 뜬다. 번호를 고르고, 빈칸이나 0 은 뒤로 가기다.

```
  1) 새 학습 시작      이름 → 시작 정책(처음부터 / 기존 학습의 최신 정책 / 스냅샷 폴더) → 메모
                       → 추가 언리얼 옵션 → 실행 시간 → 올리기 방식 → 확인 화면 → 시작
  2) 기존 학습 이어서   표에서 번호 선택 → 실행 시간 → 올리기 방식 → 시작 (처음 설정 그대로, 최신 스냅샷부터)
  3) 학습 현황 보기     전체 표(상태 · 누적 · 스냅샷 수 · 마지막 저장 · push 수 · 메모)
                       → 번호를 고르면 설정과 스냅샷별 git 상태(push 됨 / 커밋됨(로컬) / 커밋 전)
  4) GitHub 로그인 설정  저장된 로그인 확인(push 권한 검사) · 새로 입력 · 지우기
  0) 종료
```

확인 화면에서 `n` 을 고르면 아무 폴더도 만들지 않고 메뉴로 돌아간다.

## GitHub 로그인

push 하는 학습을 시작하면 **학습 전에** 로그인을 확인한다(몇 시간 뒤 로그인 창이 떠서 멈추지 않게).

- 처음에는 GitHub 사용자 이름과 **개인 액세스 토큰**을 묻는다. 토큰 입력은 화면에 보이지 않는다.
  - 만드는 곳: GitHub → Settings → Developer settings → Personal access tokens
  - Fine-grained 권장: Resource owner `HanyangTechAI`, 저장소 `2026-2-HAI-ProjectTeam5` 만, Contents **Read and write**, 만료일 지정
  - 조직에 SSO 가 걸려 있으면 토큰에서 Configure SSO → Authorize 도 한다.
- 입력하면 `git push --dry-run` 으로 **push 권한까지** 확인한 뒤 `Training/.env` 에 저장한다. 다음부터는 묻지 않는다.
- `Training/.env` 는 `.gitignore` 로 git 에 올라가지 않는다. 지우면 다음에 다시 묻는다.
- 토큰은 이 실행기가 띄우는 git 에만 **환경 변수**로 넘긴다. git 설정 파일 · 명령줄에 남지 않고, Windows 자격 증명 창도 띄우지 않는다.
- 저장된 토큰이 만료되면 학습 시작 때 다시 묻는다. 입력을 건너뛰면 그 실행은 **커밋만** 하고 push 하지 않는다.
- 메뉴 4번(GitHub 로그인 설정)에서 확인 · 바꾸기 · 지우기, 명령줄은 `train.bat --login`.

## 쓰는 법 — 명령줄 (메뉴 없이 바로)

| 하고 싶은 것 | 명령 |
|---|---|
| 메뉴 | `train.bat` |
| A 를 학습(없으면 처음부터, 있으면 최신 스냅샷부터 이어서) | `train.bat A` |
| 보상 함수를 바꾼 뒤 A 는 두고 B 로 새로 학습 | (C++ 수정 → 빌드) → `train.bat B --note "무엇을 바꿨는지"` |
| B 를 A 의 최신 정책에서 시작 | `train.bat B --from A` |
| 새 학습에 언리얼 옵션 추가 | `train.bat C -- -SHApproach=1 -SHTeamSpirit=0.5` |
| 이번에는 8시간만 | `train.bat A --hours 8` |
| 커밋만, push 는 안 함 | `train.bat A --no-push` |
| 현황 표만 보기 | `train.bat --list` |

멈추기: 창에서 **Ctrl+C**. 언리얼을 정상 종료시키고 저장된 스냅샷을 올린 뒤 끝난다.
마지막 정각 스냅샷 이후의 학습분은 저장되지 않는다 → 다음에 같은 이름으로 실행하면 그 스냅샷부터 이어진다.

## 동작

1. 같은 이름이 있으면 `run.json` 의 설정 그대로, 가장 누적 시간이 긴 스냅샷에서 `-SHResume` 으로 이어서 학습한다.
   새 이름이면 `run.json` 을 만들고 처음부터(또는 `--from` 의 정책에서) 시작한다.
   **설정(언리얼 옵션)을 바꾸고 싶으면 새 이름을 쓴다.** 이미 있는 이름에 준 `--from` · 추가 옵션은 무시한다.
2. 언리얼 실행 옵션: `Lvl_SHTrain -game -nullrhi`, `-SHSnapshotRoot=Training/<이름>`, `-SHSnapshotFlat=1`, `-SHSnapshotInterval=3600`,
   기본 학습 옵션 `-SHSelfPlay=1 -SHRoundRules=1 -SHOutcome=0 -SHReportInterval=60`(누적 16시간 학습과 같음) + 추가 옵션.
3. 30초마다 새 스냅샷을 찾는다. 마지막 파일을 쓴 뒤 20초가 지난 폴더만 "저장 끝" 으로 본다.
4. 그 스냅샷 폴더 · `run.json` · 날짜별 기록만 **경로를 지정해** 커밋한다 — 따로 스테이지해 둔 다른 파일은 섞이지 않는다.
   그 다음 `git push origin preMerge`. 거부되면 `git pull --no-rebase` 로 병합한 뒤 다시 push 한다.
5. 언리얼이 비정상 종료되면 30초 뒤 최신 스냅샷부터 다시 시작한다. 3분 안에 3번 연속 죽으면 설정 문제로 보고 멈춘다.

## 주의

- **학습 코드를 바꿨으면 실행 전에 빌드한다.** 실행기는 빌드하지 않는다. 오래된 빌드면 스냅샷이 `Training/<이름>/<날짜>/` 에 생긴다(그래도 찾아서 올린다).
- **커밋은 지금 체크아웃된 브랜치가 `preMerge` 일 때만 한다.** 다른 브랜치면 커밋을 미루고 학습은 계속한다(돌아오면 그때 올린다).
- push 는 `preMerge` 의 **모든 로컬 커밋**을 올린다. 올리기 싫은 로컬 커밋이 있으면 `--no-push` 로 돌린다.
- 병합 충돌이 나면 커밋은 로컬에 남고 학습은 계속된다. 손으로 `git pull` 해서 풀면 다음 스냅샷 때 같이 올라간다.
- 스냅샷 하나는 약 2~3 MB 다. 하루(24개)면 약 60 MB 씩 저장소가 커진다.
- 여러 이름을 동시에 돌릴 수 있다(창을 여러 개). 같은 이름을 두 창에서 돌리면 막는다. GPU · CPU 를 나눠 쓰므로 각각은 느려진다.
- git 비밀번호 창은 띄우지 않는다. push 가 인증에 실패하면 메뉴 4번(또는 `train.bat --login`)에서 토큰을 다시 넣는다.
