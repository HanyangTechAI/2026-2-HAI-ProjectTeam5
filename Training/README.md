# 자동 학습 (Training/)

`train.bat` 을 실행하면 언리얼 학습이 헤드리스로 돌고, **1시간마다 스냅샷을 저장해 git `preMerge` 에 커밋 · push** 한다.

## 폴더

```
Training/
  train.bat, train.py, README.md
  A/                         ← 학습 이름 하나 = 폴더 하나
    run.json                 ← 시작 설정(언리얼 옵션, 시작 코드의 커밋, 시작 정책, 메모)
    cum001h00m/              ← 누적 학습 시간 = 폴더 이름 = 파일 이름 앞부분
      cum001h00m_policy.bin, _encoder.bin, _decoder.bin, _critic.bin, _meta.txt
    cum002h00m/ ...
    2026-11-13.md            ← 트레이너가 쓰는 날짜별 실행 기록
    logs/                    ← 언리얼 로그 · 실행기 로그 (git 에 올리지 않음)
  B/ ...
```

## 쓰는 법 — 메뉴

`train.bat` 을 더블클릭하면 메뉴가 뜬다. 번호를 고르고, 빈칸이나 0 은 뒤로 가기다.

```
  1) 새 학습 시작      이름 → 시작 정책(처음부터 / 학습된 모델 목록에서 / 폴더 직접) → 학습 맵 · 아레나 수
                       → 학습 상대 → 메모 → 추가 언리얼 옵션 → 실행 시간 → 올리기 방식 → 확인 화면 → 시작
  2) 기존 학습 이어서   표에서 번호 선택 → 시작 지점(최신 / 이 학습의 다른 스냅샷 / 다른 모델 / 처음부터)
                       → (학습 맵 바꾸기) → (학습 상대 바꾸기) → 실행 시간 → 올리기 방식 → 확인 화면 → 시작
  3) 학습 현황 보기     전체 표(상태 · 누적 · 스냅샷 수 · 마지막 저장 · push 수 · 메모)
                       → 번호를 고르면 설정과 스냅샷별 git 상태(push 됨 / 커밋됨(로컬) / 커밋 전)
  4) GitHub 로그인 설정  저장된 로그인 확인(push 권한 검사) · 새로 입력 · 지우기
  0) 종료
```

확인 화면에서 `n` 을 고르면 아무 폴더도 만들지 않고 메뉴로 돌아간다.

## 시작 지점 (기존 학습)

| 고르는 것 | 동작 |
|---|---|
| 최신 스냅샷부터 (기본) | 지금까지처럼 이 학습의 누적 시간이 가장 긴 스냅샷에서 잇는다 |
| 이 학습의 다른 스냅샷 | 되돌아가서 다시. 예: 12시간에서 망가졌으면 10시간부터 다른 상대로 |
| 다른 학습된 모델 | `Training/` · `Snapshots/` 목록에서 고른 정책으로 이 학습을 잇는다 |
| 처음부터 | 무작위 초기화. 같은 폴더에 000h 부터 다시 쌓인다(이름이 겹치면 `_2`) — 섞이기 싫으면 새 이름 |

- 최신이 아닌 곳에서 시작하면 `run.json` 의 `start_history` 에 시각 · 그때의 최신 · 시작한 곳이 남고, 메뉴 3번 상세에 보인다.
- 실행 중에 언리얼이 죽어 다시 시작할 때는 **이번 실행이 저장한 스냅샷 중 가장 최근** 부터 잇는다(원래의 최신으로 돌아가지 않는다).
- 스냅샷 이름은 트레이너가 정한다: 시작한 스냅샷의 누적 시간 + 이번 실행 시간.

## 학습 맵

레벨은 늘 `Lvl_SHTrain` 하나이고, 그 레벨이 스폰할 **아레나 BP** 를 바꿔 끼운다(`-SHArena=<BP 이름>`, 아레나 수는 `-GymsCountOverride=N`).
목록은 `Content/RL/BP_SHArena*.uasset` 에서 만든다 — 새 아레나 BP 를 만들면 설명 없이 목록에 나온다.

| 맵 | 모양 | 인원 | 기본 아레나 수 |
|---|---|---|---|
| `BP_SHArena` (기본) | 팔각형 반경 1,750 (누적 학습에 써 온 맵) | 10 대 10 | 16 (유닛 320) |
| `BP_SHArena_Complex` | 팔각형 반경 2,450, 엄폐물 22개 | 10 대 10 | 16 |
| `BP_SHArena_Corridor` | ㄱ자 복도 — 다리 2,200 x 2, 폭 1,100, 양 끝에서 시작해 꺾이는 곳에서 만난다 | 1 대 1 | 160 (유닛 320) |

- 인원은 아레나 BP 의 `UnitsPerTeam` 이 정한다. 1 대 1 은 아레나당 유닛이 2명이라 아레나를 많이 둬야 10 대 10 과 비슷한 양을 모은다.
- **관측 크기는 맵 · 인원과 상관없다**(보이는 적 · 아군이 최대 10 · 9 의 집합). 10 대 10 에서 학습한 모델을 복도 1 대 1 에서 이어서 학습할 수 있고, 반대도 된다.
- 이어서 학습할 때 맵을 바꾸면 `run.json` 의 `map_history` 에 시각 · 그때의 누적 · 이전/이후 맵이 남는다.
- 혼합 상대의 아레나 수(스냅샷 N · 봇 M)는 맵의 아레나 수 안에서 고른다. 맵을 바꿔 합이 넘치면 16 중 6 · 2 비율로 줄인다.
- 명령줄: `train.bat C --map corridor`, `--map complex`, `--map basic`, `--map BP_SHArena_X`, 아레나 수 `--arenas 100`.
  이미 있는 학습에 주면 맵을 바꾼다.
- 추가 옵션 칸에 `-SHArena=` · `-GymsCountOverride` 를 직접 적으면 막는다(맵은 `run.json` 의 `"map"` 으로만 정한다).
- ★ `-SHArena` 는 트레이너 빌드가 필요하다(2026-11-20 추가). 그 전 빌드로 돌리면 옵션이 무시되고 기본 맵으로 학습한다.

## 학습 상대

새 학습을 만들 때 고르고, **기존 학습을 이어서 할 때도 바꿀 수 있다**(메뉴 2번 → "학습 상대를 바꿀까" y).
바꾼 시각 · 그때의 누적 시간 · 이전/이후 상대가 `run.json` 의 `opponent_history` 에 남고, 메뉴 3번 상세 화면에 보인다.

| 상대 | 뜻 | 언리얼 옵션(실행기가 만든다) |
|---|---|---|
| self-play (기본) | 같은 정책끼리 | `-SHSelfPlay=1` |
| 스크립트 봇 | 고정 규칙 상대(`ASH_ScriptBotController`) | `-SHSelfPlay=0` |
| 학습된 모델 하나 | 고른 스냅샷과만, 모든 아레나에서 | `-SHOpponentMix=1 -SHMixSnapshot=999 -SHMixBot=0 -SHOpponentPool=<스냅샷> -SHOpponentPoolOnly=1` |
| 혼합 | 아레나를 과거 스냅샷 N · 봇 M · 나머지 self-play 로 나눈다. 스냅샷 상대는 10분마다 풀에서 바꾼다(지는 상대일수록 자주) | `-SHOpponentMix=1 -SHMixSnapshot=N -SHMixBot=M [-SHOpponentPool=<폴더>]` |

- "학습된 모델" 목록은 `Training/<이름>/cum…` 과 `Snapshots/<날짜>/cum…` 에서 만든다. 관측 크기가 다른 모델을 고르면 경고한다
  (관측 크기가 지금 코드와 다르면 상대 정책이 무작위로 싸운다 — 트레이너는 에러를 내지 않는다).
- 혼합의 풀: 기본은 이 학습이 저장한 스냅샷. 다른 학습 폴더나 `Snapshots/<날짜>` 를 더할 수 있다.
- 명령줄: `train.bat A --opponent bot`, `--opponent self`, `--opponent mix`, `--opponent START_11_13`(그 학습의 최신 모델),
  `--opponent Snapshots/2026-10-25/cum016h00m`. 이미 있는 학습에 주면 상대를 바꾼다.
- 상대 옵션은 `run.json` 의 `"opponent"` 로만 정한다. 추가 옵션 칸에 `-SHSelfPlay` 등을 직접 적으면 막는다.
- ★ "학습된 모델 하나" 는 트레이너의 `-SHOpponentPoolOnly` 가 필요하다(2026-11-16 추가) — 그 전 빌드로 돌리면 1시간 뒤부터 자기 스냅샷과도 싸운다.

## GitHub 로그인

push 하는 학습을 시작하면 **학습 전에** 로그인을 확인한다(몇 시간 뒤 로그인 창이 떠서 멈추지 않게).

- 처음에는 GitHub 사용자 이름과 **개인 액세스 토큰**을 묻는다. 토큰 입력은 화면에 보이지 않는다.
  - 만드는 곳: GitHub → Settings → Developer settings → Personal access tokens
  - Fine-grained 권장: Resource owner `HanyangTechAI`, 저장소 `2026-2-HAI-ProjectTeam5` 만, Contents **Read and write**, 만료일 지정
  - 조직에 SSO 가 걸려 있으면 토큰에서 Configure SSO → Authorize 도 한다.
- 입력하면 `git push --dry-run` 으로 **push 권한까지** 확인한 뒤 `Training/.env` 에 저장한다. 다음부터는 묻지 않는다.
- `Training/.env` 는 `.gitignore` 로 git 에 올라가지 않는다. 지우면 다음에 다시 묻는다.
- 토큰은 이 실행기가 띄우는 git 에만 **환경 변수**로 넘긴다. git 설정 파일 · 명령줄에 남지 않고, Windows 자격 증명 창도 띄우지 않는다.
- 저장된 토큰이 만료되면 학습 시작 때 다시 묻는다. 입력을 건너뛰면 그 실행은 **커밋만** 하고 push 하지 않는다.
- 메뉴 4번(GitHub 로그인 설정)에서 확인 · 바꾸기 · 지우기, 명령줄은 `train.bat --login`.

## 쓰는 법 — 명령줄 (메뉴 없이 바로)

| 하고 싶은 것 | 명령 |
|---|---|
| 메뉴 | `train.bat` |
| A 를 학습(없으면 처음부터, 있으면 최신 스냅샷부터 이어서) | `train.bat A` |
| 보상 함수를 바꾼 뒤 A 는 두고 B 로 새로 학습 | (C++ 수정 → 빌드) → `train.bat B --note "무엇을 바꿨는지"` |
| B 를 A 의 최신 정책에서 시작 | `train.bat B --from A` |
| 새 학습에 언리얼 옵션 추가 | `train.bat C -- -SHApproach=1 -SHTeamSpirit=0.5` |
| 이번에는 8시간만 | `train.bat A --hours 8` |
| A 를 예전 스냅샷에서 다시 | `train.bat A --start Training/A/cum005h00m` |
| A 를 처음부터 다시(같은 폴더) | `train.bat A --start scratch` |
| 복도 1 대 1 맵으로 새 학습 | `train.bat D --map corridor` (아레나 수 `--arenas 100`) |
| A 를 이제부터 복도 맵에서 | `train.bat A --map corridor` |
| 커밋만, push 는 안 함 | `train.bat A --no-push` |
| 현황 표만 보기 | `train.bat --list` |

멈추기: 창에서 **Ctrl+C**. 언리얼을 정상 종료시키고 저장된 스냅샷을 올린 뒤 끝난다.
마지막 정각 스냅샷 이후의 학습분은 저장되지 않는다 → 다음에 같은 이름으로 실행하면 그 스냅샷부터 이어진다.

## 동작

1. 같은 이름이 있으면 `run.json` 의 설정 그대로, 가장 누적 시간이 긴 스냅샷에서 `-SHResume` 으로 이어서 학습한다.
   새 이름이면 `run.json` 을 만들고 처음부터(또는 `--from` 의 정책에서) 시작한다.
   **설정(언리얼 옵션)을 바꾸고 싶으면 새 이름을 쓴다.** 이미 있는 이름에 준 `--from` · 추가 옵션은 무시한다.
2. 언리얼 실행 옵션: `Lvl_SHTrain -game -nullrhi`, `-SHSnapshotRoot=Training/<이름>`, `-SHSnapshotFlat=1`, `-SHSnapshotInterval=3600`,
   기본 학습 옵션 `-SHSelfPlay=1 -SHRoundRules=1 -SHOutcome=0 -SHReportInterval=60`(누적 16시간 학습과 같음) + 추가 옵션.
3. 30초마다 새 스냅샷을 찾는다. 마지막 파일을 쓴 뒤 20초가 지난 폴더만 "저장 끝" 으로 본다.
4. 그 스냅샷 폴더 · `run.json` · 날짜별 기록만 **경로를 지정해** 커밋한다 — 따로 스테이지해 둔 다른 파일은 섞이지 않는다.
   그 다음 `git push origin preMerge`. 거부되면 `git pull --no-rebase` 로 병합한 뒤 다시 push 한다.
5. 언리얼이 비정상 종료되면 30초 뒤 최신 스냅샷부터 다시 시작한다. 3분 안에 3번 연속 죽으면 설정 문제로 보고 멈춘다.

## 주의

- **학습 코드를 바꿨으면 실행 전에 빌드한다.** 실행기는 빌드하지 않는다. 오래된 빌드면 스냅샷이 `Training/<이름>/<날짜>/` 에 생긴다(그래도 찾아서 올린다).
- **커밋은 지금 체크아웃된 브랜치가 `preMerge` 일 때만 한다.** 다른 브랜치면 커밋을 미루고 학습은 계속한다(돌아오면 그때 올린다).
- push 는 `preMerge` 의 **모든 로컬 커밋**을 올린다. 올리기 싫은 로컬 커밋이 있으면 `--no-push` 로 돌린다.
- 병합 충돌이 나면 커밋은 로컬에 남고 학습은 계속된다. 손으로 `git pull` 해서 풀면 다음 스냅샷 때 같이 올라간다.
- 스냅샷 하나는 약 2~3 MB 다. 하루(24개)면 약 60 MB 씩 저장소가 커진다.
- 여러 이름을 동시에 돌릴 수 있다(창을 여러 개). 같은 이름을 두 창에서 돌리면 막는다. GPU · CPU 를 나눠 쓰므로 각각은 느려진다.
- git 비밀번호 창은 띄우지 않는다. push 가 인증에 실패하면 메뉴 4번(또는 `train.bat --login`)에서 토큰을 다시 넣는다.
